# Контроль качества снимка данных

## Назначение

Проверить, что успешный запуск ingestion действительно создал пригодный для
трансформаций снимок данных. Runbook применим к любому источнику, который
пишет исходные записи в Bronze и использует идентификатор снимка.

## Когда запускать

- после подключения нового источника;
- после изменения поисковых параметров или маппинга payload;
- перед запуском аналитической витрины или демонстрацией данных;
- при зелёном DAG, если есть сомнения в полноте или свежести результата.

## Условия готовности

Для самого свежего `snapshot_id` должны выполняться одновременно:

- в Bronze есть хотя бы одна запись;
- технический идентификатор сущности заполнен;
- в рамках `(snapshot_id, search_key, entity_id)` нет повторов;
- выполнены все ожидаемые поисковые комбинации или запросы;
- в логах запуска нет скрытого `skip`, блокировок доступа, rate limit,
  аварийного завершения процесса или ошибок памяти;
- записи Silver и Gold строятся только после успешной проверки Bronze.

## Минимальные SQL-проверки

Подставить актуальные базу, таблицу и имена полей из DDL, не угадывать их.

```sql
-- Объём самого свежего снимка
SELECT snapshot_id, count() AS rows
FROM <bronze_database>.<bronze_table>
GROUP BY snapshot_id
ORDER BY max(ingested_at) DESC
LIMIT 1;

-- Пустые технические идентификаторы
SELECT count() AS empty_ids
FROM <bronze_database>.<bronze_table>
WHERE snapshot_id = '<snapshot_id>'
  AND (entity_id IS NULL OR entity_id = '');

-- Повторы в пределах снимка и поискового запроса
SELECT snapshot_id, search_key, entity_id, count() AS duplicates
FROM <bronze_database>.<bronze_table>
WHERE snapshot_id = '<snapshot_id>'
GROUP BY snapshot_id, search_key, entity_id
HAVING duplicates > 1
ORDER BY duplicates DESC
LIMIT 10;

-- Полнота поискового набора
SELECT search_key, count() AS rows
FROM <bronze_database>.<bronze_table>
WHERE snapshot_id = '<snapshot_id>'
GROUP BY search_key
ORDER BY search_key;
```

## Интерпретация

- Нулевой объём, пустые идентификаторы или дубли — снимок нельзя передавать
  дальше без отдельного диагноза.
- Отсутствующий поисковый ключ означает неполный снимок, даже если DAG green.
- Разница между количеством Bronze и Silver допустима только при документированной
  дедупликации или фильтрации; сравнивать нужно на определённой grain-модели.
- Если проверка не пройдена, не удалять исторические снимки: сохранить их для
  расследования и исправлять причину отдельным изменением.

## Фиксация результата

В отчёте сохранять: время запуска, `snapshot_id`, ожидаемое и фактическое
число поисковых комбинаций, объём Bronze, число пустых идентификаторов,
число дублей и вывод о пригодности снимка для следующего слоя.
